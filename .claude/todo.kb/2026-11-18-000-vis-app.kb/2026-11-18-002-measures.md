# `measures.py`: the DPS numbers a player can check in-game

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 1)

## Problem Statement

Implement the design's "Measures" section as a pure module. Its consumer is
wave 2's `timeline` query, which writes each measure as one
`{"kind": "measure", "name", "value", "unit", "check"}` line, so give each
measure exactly those fields.

Each `check` is a short instruction to the player: where in-game to read or
time the value (the hero's stat panel, the sandbox training dummy, a stopwatch
from first trigger). Write checks that a player can follow.

Cover the edge cases with tests:
- a cycle with no period (`period=None`): uptime and steady DPS are undefined,
  so omit them, don't emit 0;
- `period == reload`;
- `hp` not given, and `hp` never reached within the horizon;
- zero hits.

`uptime_dps` must reproduce the in-game UI DPS for the fixtures in
`timeline_test.py` (Seven 63, Paige 64, Abrams 54). Reuse those numbers, but
don't import from a test module; copy the three `Gun(...)` literals.

**Scope (only these files):** `apps/vis/server/src/vis_server/measures.py`,
`apps/vis/server/src/vis_server/measures_test.py`
