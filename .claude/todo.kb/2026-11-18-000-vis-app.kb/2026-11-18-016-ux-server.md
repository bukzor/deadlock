# UX round, server side: player-facing measures and notes; horizon and hits match

**Parent:** <https:../2026-11-18-000-vis-app.md> (review round 2)

## Problem Statement

Implement the server half of unit 015's findings, as the amended design
states them. Unit 017 builds the client half in parallel, against the design's
protocol.

- **Finding 1: measures a player can anchor on.** Give each measure line a
  `label` in player words, for example:
  - "DPS while active (≈ stat panel for guns)";
  - "DPS incl. reload/cooldown";
  - "Damage per cycle".

  Order the lines so the one comparable to the card comes first.
  `average_dps` stays: it is the DPS over the first N seconds, which is useful
  for burst. Its label says so ("DPS over the first {horizon} s").

  Omit `uptime_dps` for a cycle with a single hit. Today an impact-only cast
  reads damage ÷ cast delay, for example 400/s (unit 013's open question).
- **Finding 3, as the user amended it: the horizon default.** The user's words:
  "\"horizon\" should have two mutually-updating inputs: seconds (as currently)
  and \"x period\" (default 2) -- so by default we see two \"full cycles\" of
  damage".
  - When `horizon` is absent, use exactly 2 periods, with no 10 s floor.
  - A cycle with no period gets 10 s.
  - Emit the design's new first line, `{"kind": "cycle", "period",
    "downtime", "horizon"}`, so the client can convert between seconds and
    periods.
  - Update the param's description in `QUERIES`.
- **Finding 7: notes for players.** Rewrite each source's notes in player
  terms, with no engine field names in the prose. For example, "Upgrades not
  included: T2 cooldown −10 s, …". Order the notes by how much each caveat
  moves the numbers; level 0 and no items goes first.
- **Finding 9: send only what the totals count.** `timeline` sends only hits
  that land within the horizon.
- **Ledger.** File these as `standing: agent` claims in
  `apps/vis/docs/dev/claims.kb/`:
  - the cumulative-damage line as the main read, with the bars kept per the
    user's spec (finding 2);
  - a per-kind caption for bar width, with damage-over-time ticks keeping
    their width (finding 4);
  - selection in the URL now, comparison overlays deferred (finding 6);
  - the horizon default;
  - `average_dps` kept and relabelled.

  Each one cites unit 015's report and the user's request for that review.

All checks must be clean: pytest and basedpyright `all`. Also run the CLI
`timeline` query for Nurse Harrow's leech, a gun and Flame Dash, and put the
output in the Final report.

## Decisions

- New measure `cycle_damage` ("Damage per cycle", the brief's third label), placed after `steady_dps`.
- A one-hit cycle loses `uptime_dps`, so light/heavy melee and impact-only casts show `steady_dps` first.
- Notes: `LEVEL_ZERO` first, then each source's by rank (cast: left-out damage, upgrades, charges, overlap, no cooldown, unverified; gun: falloff, reload, speed). The `hp`-not-reached note is last.
- Dropped the cast note about non-standard duration/tick field names: it names engine fields and means nothing to a player.
- Engine names in notes are turned to words by `casts._humanize` (`AbilityCooldown` -> "cooldown"); upgrade bonuses print as the data gives them ("-10").
- Ledger claims sit in `claims.kb/` (not `model.kb/`): `cumulative-line`, `bar-width-caption`, `url-selection`, `horizon-default`, `average-dps-kept`.
