# `casts.py`: signature and ultimate damage as a `Cycle`

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 1)

## Problem Statement

Implement the design's "Cast" source. Given the loaded trees, a hero, an
ability key and `spirit`, return `(Cycle, notes)`, or `None` when the key isn't
one of the hero's bound signatures or ultimate, or has no `Damage`/`DPS`.
Properties are `m_mapAbilityProperties.X.m_strValue` strings; nearly all are
numeric, with known exceptions such as `"0.1m"` and `"40 30 20"`. Parse
strictly: a non-numeric value in a field you read is a `BadRequest` or a note,
your call; document which.

This model is an unverified heuristic, so the first note says so. Each
unmodeled factor present on the ability (charges, upgrades, a property that
looks damage-relevant but isn't read) gets its own note. Survey the real data
so the notes cover what actually occurs. Record the survey's counts in the
module docstring, not in a doc: the design doc belongs to the coordinator.

Tests: unit tests on synthetic trees, plus a test over the real data that every
bound signature and ultimate either yields a cycle or returns `None`, without
raising (skipped when the data is absent).

**Scope (only these files):** `apps/vis/server/src/vis_server/casts.py`,
`apps/vis/server/src/vis_server/casts_test.py`
