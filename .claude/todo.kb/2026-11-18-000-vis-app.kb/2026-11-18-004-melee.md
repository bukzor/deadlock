# `melee.py`: light and heavy melee as a `Cycle`

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 1)

## Problem Statement

Implement the design's "Melee" source for the pseudo-abilities `melee_light`
and `melee_heavy`. Given the loaded heroes tree, a hero, the ability key and
`windup` (seconds), return `(Cycle, notes)`, or `None` for any other key. Read
the damage and cooldown from the fields the design names. Find the hero's
fields through the same `_base` inheritance that `deadlock` uses elsewhere; grep
`src/deadlock/` for how heroes resolve `_base`.

The wind-up is not in the data, so the note says so and names the parameter.
The heavy cooldown on a miss (1.3) differs from on a hit (1.0). Model hits, and
say so in a note.

The user's in-game numbers are in `docs/games/melee.txt` (read-only, never
stage it). Its "pulse" column's meaning is unknown, so don't build on it.

Tests: unit tests on synthetic trees, plus a test over the real data that every
live hero yields both melee cycles (skipped when the data is absent).

**Scope (only these files):** `apps/vis/server/src/vis_server/melee.py`,
`apps/vis/server/src/vis_server/melee_test.py`
