# `melee.py`: light and heavy melee as a `Cycle`

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 1)

## Problem Statement

Implement the design's "Melee" source for the pseudo-abilities `melee_light`
and `melee_heavy`. Given the loaded heroes tree, a hero, the ability key and
`windup` (seconds), return `(Cycle, notes)`, or `None` for any other key. Read
the damage and cooldown from the fields the design names. Find the hero's
fields through the same `_base` inheritance that `deadlock` uses elsewhere; grep
`src/deadlock/` for how heroes resolve `_base`.

The wind-up is not in the data, so the note says so and names the parameter.
The heavy cooldown on a miss (1.3) differs from on a hit (1.0). Model hits, and
say so in a note.

The user's in-game numbers are in `docs/games/melee.txt` (read-only, never
stage it). Its "pulse" column's meaning is unknown, so don't build on it.

Tests: unit tests on synthetic trees, plus a test over the real data that every
live hero yields both melee cycles (skipped when the data is absent).

**Scope (only these files):** `apps/vis/server/src/vis_server/melee.py`,
`apps/vis/server/src/vis_server/melee_test.py`

## Decisions

- **Signature `melee_cycle(heroes, abilities, hero, ability, windup)`**, not
  the heroes tree alone: the cooldowns are not on the hero (below). Argument
  order matches `guns.hero_gun_cycle`.
- **Cooldowns come from the bound melee ability.** `m_mapAttacks` is absent
  from `heroes.json`; it lives on the ability each hero binds to
  `ESlot_Weapon_Melee` in `abilities.json`. One hero differs: punkgoat's light
  cooldown is 0.65 s.
- **No `_base` resolution.** `deadlock` never resolves `_base`: heroes carry
  materialized `m_mapStartingStats` (see `deadlock.heroes`), and the melee
  abilities have no `_base`. Every live hero has both damage stats.
- **The miss note is conditional.** It appears only when the cooldown on a miss
  differs from the cooldown on a hit (heavy: 1.0 vs 1.3), and it quotes the
  data's values. Light melee is the same either way, so it gets no miss note.
- **Bad input is a `BadRequest`:** an unknown hero, or `windup < 0`.

## Open Questions

- **The `deadlock` package lacks `py.typed`.** basedpyright reports
  `reportMissingTypeStubs` on every `deadlock` import. Adding an empty
  `src/deadlock/py.typed` (out of my scope) clears it: 0 errors here then. This
  hits guns and casts too.
- **The data and the user's numbers differ widely.** Light melee damage is
  50-63 in the data, but `docs/games/melee.txt` reads 233-370. Level scaling
  (`MODIFIER_VALUE_BASE_MELEE_DAMAGE_FROM_LEVEL`) is not modeled, and the
  module docstring says so. Should a note say it too?
- Siblings name their entry points differently: `hero_gun_cycle`, `cycle`,
  and `melee_cycle` here. Wave 2 may want one convention.
