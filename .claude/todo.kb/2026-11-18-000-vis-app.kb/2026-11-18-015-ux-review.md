# UX review: is the vis UI intelligible, and does it serve the user's goal?

**Parent:** <https:../2026-11-18-000-vis-app.md> (review round 1)

## Problem Statement

The user asked for "a sub-agent to ponder the intelligibility and overall UX
of this UI", and supplied the screenshot above. Their stated vision, from the
original request: "a damage versus time graph, with bars that have damage as
high, left side as triggering event, right side as actual time of damage
(width as 'wind up time')", plus "various dps measurements (that are
checkable in-game)".

Work from first principles, with no checklist. Who uses this? A Deadlock
player.
- **What they want:** reason out what that player would come to this page
  wanting to learn or decide, and what they would expect to see.
- **What they understand:** what they would and wouldn't understand on
  arrival, without our vocabulary.
- **The gap:** derive where this UI meets them and where it doesn't, from
  that model. Show the reasoning, then the findings that follow from it.

**Already decided; don't report these again.** The user has already seen,
and fixed, the following:
- **Unit 013, in flight:**
  - damage-over-time ticks tile (previous tick → land) instead of all
    overlapping from the cast, which is what caused the shading;
  - `uptime_dps` covers every source via a cycle's downtime, so for an ability
    it exceeds `steady_dps`;
  - the "for a gun" special case leaves the check text;
  - a readable bar fill and a plain tooltip;
  - the x axis covers every bar.
- **Unit 014, queued:** `bin/serve` reloads live (Vite plus uvicorn reload).

Skill(dataviz) is disabled for model invocation, as unit 012 found, so apply
dataviz judgement yourself. If you want fresh screenshots, the user's `serve`
is on `http://localhost:8787`.
- Read it only; never stop it.
- It predates unit 013.
- Drive it the way unit 012 did, and save the screenshots in `trash/015/`.

**Deliverable: findings only, no code.** Units 013 and 014 are editing the
client and server now. Write the findings in this file's Final report, ranked
by how much each one hurts the user's goal. For each finding give:
- what the user sees;

Flag any finding that is a judgement the user should make, rather than a
defect.
