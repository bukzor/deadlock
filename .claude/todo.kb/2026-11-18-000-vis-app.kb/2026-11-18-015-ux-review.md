## Final report

**Player model.** A Deadlock player comes to this page with a decision: which ability or build hits harder, whether spirit is worth it, how long a kill takes. The numbers they already know are on the ability card (Damage, DPS, Duration, Cooldown) and the weapon stat panel. They don't know `uptime`/`steady`, `AbilityCastDelay`, or that "trigger → land" is a bar's width. So the page works when its top number matches a number they know, and the rest explains how that number turns into damage over a fight. Today it leads with an engineer's ledger. Ranked by harm to the goal of a damage-vs-time chart plus DPS numbers you can check in-game:

1. **No DPS number to anchor on (S).** *Sees:* four unranked measures named in code (`uptime_dps`, `steady_dps`, `average_dps`, `first_land`), and they disagree. `average_dps` beats `steady_dps` whenever damage is front-loaded: Kelvin icebeam 22.5 vs 8.04, Flame Dash 9 vs 2.37, light melee 70 vs 66.67. *Why it misleads:* the player can't tell which one is "the DPS", and none matches the card. Flame Dash's card says DPS 30; the page says 28.1 (the 0.7 s cast delay is folded in) and doesn't say why. *Fix:* first show a row of the card's own values from the data (Damage/DPS/Duration/Cooldown, or clip, fire rate and reload), then name the measures in player words: "DPS while firing/active (≈ stat panel)", "DPS over full cycles incl. reload/cooldown", "damage per cast/clip". Drop `average_dps`: it is `total_damage ÷ horizon`, so it measures the horizon you picked, not the ability.
2. **Bar height isn't damage output (M; judgement: the user specified height = damage).** *Sees:* heavy melee is 116 tall, Infernus' gun is 5.5. Leech ticks are 8.74 tall, and they would be half that if the tick rate doubled at the same DPS. *Why it misleads:* the eye reads height and area as "how much damage". Here height is the size of one hit, and area is damage × wind-up, which means nothing. *Fix:* keep the bars, and add a cumulative-damage step line on a right axis as the main read. Its slope is DPS, a dashed `hp` line gives time-to-kill at a glance, and a single line compares gun, melee and cast fairly. Relabel the y axis "damage per hit". This promotes the Later item "cumulative line for dense DoT" from a niche to the core.
3. **The default horizon hides the cycle (S).** *Sees:* at 10 s, every cast shows one burst and then empty space. Flame Dash's cycle is 38 s, so the next cast comes at 40.7 s. *Why it misleads:* `steady_dps` (2.37) describes a cooldown that is never drawn, so the chart and the table tell different stories. *Fix:* have the server default `horizon` to about 2 periods (e.g. `max(10, 2×period)`) and fill the box with the value it used.
4. **"Wind-up" width is mostly invisible or means something else (S; judgement).** *Sees:* gun bars are hairlines. Infernus at 30 m travels 0.045 s against 0.105 s between shots, about 5 px. Melee width is a number the player types. A DoT tick's width is the tick interval, not a wind-up. *Why it misleads:* the axis caption "bar spans trigger → land" promises a reading that only cast delays deliver. *Fix:* put a caption per source naming what the width is ("bullet travel", "time since previous tick", "assumed wind-up"). The user should decide whether DoT ticks should carry width at all.
5. **Every knob shows for every ability (S).** *Sees:* spirit power on a gun and distance on a cast change nothing, silently. The grey placeholders "0"/"none" read as entered values. *Fix:* show only the knobs that apply to the ability's `kind` (the abilities line already carries it). Write defaults as "default 10".
6. **One selection, no state to keep (M; judgement: beyond the first goal).** *Sees:* one hero and one ability at a time, and a reload or a shared link loses the setup. *Why it hurts:* the player's decisions are comparisons (A vs B, spirit 0 vs 100), and so is this repo's purpose (patch diffs). *Fix:* put the params in the URL (S), then overlay a second selection's cumulative line (M). Patch-vs-patch is L.
7. **Notes speak engine (S).** *Sees:* "unverified heuristic: Damage lands at AbilityCastDelay…" and "T1 LeechStaminaDrain 0.3". The caveat that most affects matching in-game, "level 0, no items", comes last. *Fix:* rewrite for players ("Not yet checked in-game", "Upgrades not included: T2 cooldown −10 s, …") and order by how much each caveat moves the numbers.
8. **Hover target is a 2 px rule (S).** The tip sits on `ruleX` at land, so hovering a (now tiled) bar's body shows nothing, or shows the neighbour's land. *Fix:* put the tip on the rect, or use `Plot.pointerX`. 013 changes the tip's content, not its target.
9. **The chart draws damage the totals exclude (S).** Leech at horizon 30: the server sends cycle 1's tick (trigger 30, land 30.48), but `total_damage` (113.62 = 13 ticks) counts cycle 0 only. Once 013 widens the x domain, that bar draws in full. *Fix:* send only hits whose land ≤ horizon, matching the measures.
10. **Title collides with the game term (S).** In Deadlock, "Damage over time" means DoT, so a player expects a DoT-only view. *Fix:* rename it "Damage timeline".

Not re-reported (already in 013/014 or the plan's Later list): ability keys instead of names, the 14 casts that draw nothing (Afterburn's "No damage lands within the horizon" is the misleading wording there), level scaling, upgrades.
