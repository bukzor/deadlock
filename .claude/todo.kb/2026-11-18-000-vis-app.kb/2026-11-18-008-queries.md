# `queries.py`: the query registry (heroes, abilities, timeline)

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 2)

## Problem Statement

Implement the design's "Protocol" section on the server side. That means the
`Query` type, which goes in `types.py`, and `queries.QUERIES` with `heroes`,
`abilities` and `timeline`, emitting exactly the lines the design specifies.
Unit 009 (`http.py`, `__main__.py`) consumes `QUERIES` and `Query`, so
document both where they're defined.

- **Data.** Load the trees once per process, lazily (`deadlock.gamedata.load`,
  `deadlock.paths.data_dir()`). Hero display names come from
  `data/gamedata.tsv/heroes.tsv`. Ability display names: use what the data
  offers, or the key.
- **`abilities`.** List the hero's gun, `melee_light`, `melee_heavy`, and each
  bound signature and ultimate. `kind` is whichever source returns non-`None`;
  if none does, it is `null`.
- **`timeline` lines.** Emit every hit, then every measure, then every note:
  - the hits from `repeat`;
  - the measures from `measures.measures`;
  - the source's notes, plus the design's level-0 note;
  - a note when `hp` is given but not reached within the horizon.
- **Bad input** is a `BadRequest`:
  - an unknown hero or ability;
  - an unknown or missing parameter;
  - a non-numeric value;
  - `horizon <= 0` or `hp <= 0`, because `measures` asserts on those, and a
    negative `distance`, `spirit` or `windup`.
- **Entry points.** The design now names each source's entry point `cycle`.
  Rename `guns.hero_gun_cycle` and `melee.melee_cycle` to match, updating their
  tests. `casts.cycle` already conforms. Only the names change, not the
  behavior.
- **Tests.** Synthetic trees for the line shapes and every `BadRequest`. A
  real-data test that `timeline` runs, without raising, for every live hero ×
  every ability that `abilities` lists, skipped when the data is absent.

**Scope (only these files):** `apps/vis/server/src/vis_server/{queries,queries_test,types}.py`,
`apps/vis/server/src/vis_server/{guns,guns_test,melee,melee_test}.py`
(the rename only)

## Decisions

- **`registry(data)` builds the table; `QUERIES = registry(load_data)`.**
  `load_data` is `functools.cache`d and only called when a query runs, so
  importing needs no data and tests pass synthetic `GameData`.
- **Unknown parameters are rejected per query** by a wrapper around `run`,
  against the `Query`'s own `params`, so the listing and the check can't drift.
- **Live roster = `deadlock.abilities.bindings`**, the same set every source
  uses. A hero outside it (disabled, `hero_base`, absent) is a `BadRequest`.
- **Ability `name` is the key**: the trees hold no ability display names, and
  ability localization isn't extracted into `data/`.
- **`kind` is found at default parameters**, trying gun, melee, then cast.
- **A listed ability with `kind: null` is not a `BadRequest` in `timeline`**:
  it answers notes only, one saying no source models it, plus the level-0 note.
  That squares "unknown ability is a `BadRequest`" with the real-data test
  "every listed ability runs".
- **Non-finite numbers (`nan`, `inf`) are `BadRequest`**: `float()` accepts
  them, and `horizon=inf` would loop forever in `repeat`.
- **Notes order:** the source's, then the hp-not-reached note, then
  `LEVEL_ZERO` ("Stats are level 0, with no items.") last.
- **Renamed-entry tests call `guns.cycle` / `melee.cycle` qualified**: a bare
  `cycle` import is shadowed by the local `cycle` variables those tests use.
