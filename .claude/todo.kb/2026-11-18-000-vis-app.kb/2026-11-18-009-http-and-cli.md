# `http.py` + `__main__.py`: serve the queries over HTTP and the CLI

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 2)

## Problem Statement

Implement the design's "Protocol" section over `queries.QUERIES`, in two
modules:

- **`http.py`:** a Starlette app.
  - `GET /api` lists the queries.
  - `GET /api/{query}?k=v` answers `application/jsonl`, with lines from
    `deadlock.jsonl.dumps`.
  - A `BadRequest` becomes a 400 with one `{"error"}` line. An unknown query
    is a 404 with the same line shape.
  - Serve `../client/dist` at `/` when it exists. Absent is fine: dev uses
    Vite's proxy.
  - Tests use Starlette's `TestClient` with a fake registry: the app should
    take the registry as an argument and default to `QUERIES`.
- **`__main__.py`:** the `vis-server` script that `pyproject.toml` already
  declares.
  - `vis-server serve [--host 127.0.0.1] [--port 8787]` runs uvicorn.
  - `vis-server query NAME k=v …` prints the same lines to stdout.
  - On a `BadRequest`, it prints the error line to stderr and exits 2.
  - Test `query` in-process, including the `jq`-compatible output (one compact
    object per line).

Both paths must produce byte-identical lines for the same query. Test that.
Finish with a manual smoke run against the real data:
`uv run vis-server query timeline hero=… ability=… | jq -c .` and the same
query over `curl` with the server up.
- Run the server in the foreground under `timeout`, or start it, curl, and
  kill it in one command.
- Never leave it running.
- Put the commands and their output in the Final report.

**Scope (only these files):** `apps/vis/server/src/vis_server/{http,http_test,__main__,main_test}.py`
