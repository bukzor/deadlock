# Hero level as an input (default 0), scaling gun, melee and spirit

**Parent:** <https:../2026-11-18-000-vis-app.md> (review round 2)

## Problem Statement

The user asked, verbatim: "inputs should include a \"level\" -- 0 is a good
default, easieset to check in-game".

Today every stat is level 0 with no items. The `stat-level` claim deferred
level scaling, so this unit supersedes it.

1. **Find out from the data how hero level changes damage.**
   - Look at the boons per level and what each one grants: bullet damage,
     melee damage, spirit power, and anything else damage-relevant.
   - Check whether the melee gap (50–63 in the data against 233–370 in the
     user's `docs/games/melee.txt`) is explained by level. The user's in-game
     level for those readings is unknown, so say what level, if any, would fit.
   - Write the formulas and evidence to a new `docs/dev/mechanics.kb/` file.
     Follow that collection's CLAUDE.md: each formula comes with its evidence.
2. **Server: a `timeline` param `level`, default 0.**
   - Pass it to the sources that scale: gun damage, melee damage, and spirit
     power, which feeds cast scaling.
   - Validate its range from the data (a `BadRequest` outside it).
   - At level 0, the existing real-data tests must be unchanged.
   - Replace the level-0 note with the stated level ("Hero level N, no items").
3. **Client: a level input**, shown for every kind, default 0, kept in the
   URL like the others.
4. **Ledger.**
   - Mark `stat-level` superseded with a `verdict:`, and file the level claim
     citing the user's words.
   - Update `melee-damage-mismatch` with what you found. If level explains
     the gap, that becomes a finding; otherwise it stays an open claim.

All checks must be clean: pytest, basedpyright `all`, `tsc --noEmit` and
vitest. Run the CLI timeline at levels 0 and 10 for one hero's gun, melee
and a cast, and put the output in the Final report.

**Scope:** `apps/vis/server/src/vis_server/*`, `apps/vis/client/src/*`,
`apps/vis/docs/dev/claims.kb/model.kb/*`, and one new
`docs/dev/mechanics.kb/*.md`
