**Parent:** <https:../2026-11-18-000-vis-app.md> (review round 2)

The user asked, verbatim: "inputs should include a \"level\" -- 0 is a good
default, easieset to check in-game".

Today every stat is level 0 with no items. The `stat-level` claim deferred
level scaling, so this unit supersedes it.

   - Look at the boons per level and what each one grants: bullet damage,

## Decisions

- Level is numbered as `levels.tsv` does (game level − 1, 0 to 35); boons
  at level N = level-ups setting `m_bUseStandardUpgrade`, which is N for
  every live hero. Reason: the user's own convention, and the wiki's.
- Heavy melee per boon = light per boon × heavy/light. Reason: the data has
  one melee field; deadlock.wiki's Abrams (+4.03) and Bebop (+2.91) match.
- `spirit` is spirit power on top of the level's. Reason: as a total, a
  typed value would silently drop the level's spirit.
- Each source takes a `Boons` (`vis_server/boons.py`); casts get the summed
  spirit. Level-0 output is unchanged except the note text.
- Hero spirit scaling of bullet/heavy-melee damage (Vindicta, Grey Talon,
  Solomon, Paige) is a note, not modeled: the data doesn't settle its form.
- `HERO_LEVEL` (user) and `LEVEL_SCALING` (agent) both went in `model.kb/`,
  because the brief's scope is `model.kb/*`.
