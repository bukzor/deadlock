# `guns.py`: a hero's gun as a `Cycle`

**Parent:** <https:../2026-11-18-000-vis-app.md> (wave 1)

## Problem Statement

Implement the design's "Gun" source. Given the loaded trees, a hero and an
ability key, return `(Cycle, notes)`, or `None` if the key isn't that hero's
gun. Build the `Gun` record from the same fields `ability_profiles` reads, by
reusing its helpers where you can, so the two cannot disagree.

Travel is `distance / bullet speed`, with the speed taken from
`m_mapWeaponInfos.primary.m_BulletSpeedCurve.m_spline[].y`. The speed is
present on only a few guns, and constant on those. When it is absent, travel is
0 and a note says the speed is unknown. When the curve is not constant, fail
loudly: we don't model it.

The gun's ability key is the one `deadlock.abilities` binds to the weapon slot;
choose it and document it in the docstring. Wave 2's `abilities` query lists
it.

Tests:
- Unit tests on small synthetic trees.
- An integration test over the real `data/`: for every live hero, the cycle's
  `Σdamage / (period − reload)` equals the profile's `dps`, and
  `Σdamage / period` equals its `sdps`. Compute these inline in the test;
  `measures.py` is a sibling's, still in flight.
- If the local data is missing, the integration test skips, saying so.

**Scope (only these files):** `apps/vis/server/src/vis_server/guns.py`,
`apps/vis/server/src/vis_server/guns_test.py`

## Decisions

- **Entry point** `guns.hero_gun_cycle(heroes, abilities, hero, ability,
  distance=0.0) -> (Cycle, list[str]) | None`. `distance` is in meters. The
  name avoids a clash with `timeline.gun_cycle`.
- **Gun key:** the ability bound to `Weapon_Primary`, read from its `primary`
  profile. `Weapon_Secondary` (3 heroes) returns `None`.
- **Reuse:** the base stats come from `ability_profiles.profiles()`' row.
  Shots (`clip / m_iAmmoConsumedPerShot`) and the reload from empty re-read the
  same fields as `_gun_rates`, because those helpers are private. The real-data
  test is what keeps the two in agreement.
- **Bullet speed (differs from the brief).** All 46 live primaries set
  `m_flBulletSpeed`; only 6 have `m_BulletSpeedCurve`, and on 5 of those
  the two disagree (Silver: curve 571.5 m/s, field 812.8 m/s). The curve wins
  when present, and a note marks the disagreement as unverified. Otherwise
  the field is used. Only when both are absent is travel 0, with the
  "speed unknown" note. Following the brief exactly would have given 40 guns
  travel 0 even though the data has their speed.
- **Units:** engine units are inches (×0.0254). Evidence: the speeds and ranges
  come out round (20669.3 → 525 m/s, 669.291 → 17 m).
- **Varying curve:** raises `NotImplementedError` (no live gun has one).
- **Extra notes:** single-bullet reload from empty is unverified (per
  `gun-sustained-dps.md`); damage falloff beyond `m_flDamageFalloffStartRange`
  is not modeled (only shown when `distance` exceeds it).

## Open Questions

- Should the design doc's "speed known for only a few guns" be corrected to
  match the bullet-speed decision above? And which speed does the game actually
  use when the curve and the field disagree? Only an in-game check can tell.
- `ability_profiles` could expose its shots/reload derivation publicly, so
  that guns.py reuses the code rather than re-reading the same fields.
- Damage falloff and headshot crits (`m_flCritBonus*`) are not modeled.

## Final report

- `apps/vis/server/src/vis_server/guns.py` (109 lines) and `guns_test.py`
  (13 tests: 12 synthetic, 1 real-data). `pytest` passes and basedpyright
  `all` is clean on both (after 007's `py.typed`).
- The real-data test covers all 46 live heroes' guns: `Σdamage/(period −
  reload)` matches `dps` and `Σdamage/period` matches `sdps` within 0.051
  (the profile rounds to 0.1). It skips with the path when data is missing
  (checked against an empty `DEADLOCK_DATA_DIR`).
- Every assertion was seen to fail, from the stub, from the staged
  implementation, or from a mutant. One mutant, ignoring the profile name,
  survived on real data, because no live primary has a second profile. A
  `fakegun` profile in the synthetic tree now kills it.
- One deviation from the brief: the bullet-speed fallback (see Decisions).
