# `asr runner`: build the ASR job and start it in the background

**Parent:** <https:../2026-11-24-000-vo-transcripts.md> (wave 4)

## Problem Statement

Build the ASR side of the design doc, then start the full Yamato run
detached and hand back without waiting for it. Unit 006, the fix-up pass,
consumes the ASR ledger, and can start on its rows while the run is still
going.

Build:
- **Audio:** a redo target that decompiles the in-scope clips' `vsnd_c` to
  MP3 under `data/vo/audio/`, using VRF `-d` (see `formats.kb/vsnd.md`).
- **Models:** redo targets that fetch `ggml-small.bin` (the bulk run) and
  `ggml-large-v3-turbo.bin` (escalation; 006 uses it) into
  `data/tools/whisper/`.
- **The job:** a Python module that writes `transcripts/asr/<hero>.tsv` as
  the design doc says (scope, model id, batching, footprint). It also has a
  single-clip mode with a model choice, which 006's escalation uses. It is kill-safe and resumable. Test its pure parts
  (pending set, the clip-offset split, ledger merge) red first; the
  whisper call itself stays a thin, untested shim.
- **The view:** a redo target for `data/vo/japanese.tsv` that joins
  `lines.tsv`, the ASR ledger and `transcripts/fixups.tsv`, which may not
  exist yet. It is committed.
- **Wiring:** add `data/vo/lines.tsv` and `data/vo/japanese.tsv` to
  `data/all.do`'s `committed` list (for `redo-adopt`) and to its
  `redo-ifchange`.
- **Script:** `bin/asr-yamato` (or a better name), a ≤50-line shim that
  starts the job in tmux session `asr`.

Then start the run with that script, check that the first rows land, and
hand back. In your report, say how to watch it, how to stop it, and your
estimate of when it finishes.

Don't fix the pre-existing re-provisioning of `Source2Viewer-CLI.d` on
every build. If it gets in your way, say so in your report.

**Scope (only these files):** new `src/bukzor_deadlock/vo_asr*.py` (+
tests), new `.do` files under `data/vo/` and `data/tools/whisper*`,
`data/all.do`, `.gitignore` (if needed), `transcripts/asr/` (the ledger the
job writes; commit what has landed by hand-back), `bin/asr-*`, the
"Look facts up" paragraph of the repo `CLAUDE.md` (one clause for
`data/vo/japanese.tsv`), this file.

## Decisions

- **`all.do` is at the repo root,** not `data/all.do`; I wired that one.
- **CLI is positional,** `vo_asr HERO MODEL [CRC32...]`, house style (no
  argparse). `MODEL` is `small` or `turbo`; the ledger ids are
  `small/dtw/greedy` and `large-v3-turbo/beam5` (turbo at whisper's default
  beam 5, since escalation wants quality over speed).
- **The job renices itself** (`os.nice(19)`) and fixes 4 threads, so 006
  can't forget the CPU rule by calling it directly.
- **`OMP_NUM_THREADS` = `-t`.** brew's whisper-cli is an OpenMP build: at
  `-t 4` one clip took 4.7 s wall and 32.6 s user (about 12 threads);
  with `OMP_NUM_THREADS=4`, 3.0 s wall and 10.2 s user. At `-t 1` user
  time equals wall, so the 4 × 1 bulk run was never affected.
- **Scope rule, generalised:** "Speaks Japanese" clips, plus uncaptioned
  non-`emote/` clips only for a hero that has a "Speaks Japanese" clip.
  Yamato: 532 + 11 = 543.
- **Ledger rows sort by `vsnd`, then model,** so diffs group by event, and a
  row's `vsnd` follows its clip's current name. A clip shared by several
  events is one row, under its alphabetically first name.
- **Audio is the whole hero directory** (1806 MP3s, about 1 s): cheap, and
  for listening too. The batch WAV is written with stdlib `wave`.
- **View `source`:** the fix-up's `by` once one exists, else the raw ASR
  row's model id, else empty (no ASR yet). Model ids hold a `/`, `by`
  values don't.

## Final report

**Checks:** `pytest`, `pyright` clean; new Python `black`-clean. Every
assertion in the three `_test.py` files was seen to fail under a
hand-made mutation of its unit (`trash/vo-transcripts/005/mutate.py`).

**Run:** `bin/asr-start yamato` ran the whole Yamato set before
hand-back: 543 clips (532 "Speaks Japanese" + 11 uncaptioned), 63
batches, 290 s, exit 0, so there was no tail to wait on. No clip came back
empty. A rerun finds 0 pending (resume holds).
`transcripts/asr/yamato.tsv` has 543 rows of `small/dtw/greedy`, and
`data/vo/japanese.tsv` has 543 rows with raw ASR text and an empty
translation, ready for 006.

**Watch / stop:** `tmux attach -t asr` or `wc -l transcripts/asr/*.tsv`;
`tmux kill-session -t asr`. The pane stays open after the job exits, so
kill it before the next start. Escalation for 006:
`./bin/shell python -m bukzor_deadlock.vo_asr yamato turbo CRC32...`.

**Where things are:** interfaces in the docstrings of
`src/bukzor_deadlock/vo_asr{,_ledger,_batch,_view}.py`; targets
`data/tools/whisper/default.bin.do`, `data/vo/{audio/default.d,japanese.tsv}.do`.

**Re-provisioning:** each build touching the VRF CLI re-provisions
`Source2Viewer-CLI.d` (twice per `bin/asr-start`, about 5 s each): time,
not correctness. Not fixed.
