# `vpk explode`: raw files out of every install VPK, by redo

**Parent:** <https:../2026-11-24-000-vo-transcripts.md> (wave 1)

## Problem Statement

The owner wants one generic extraction step that explodes files from the
VPKs, so every later extraction (captions, soundevents, audio, and others
to come) starts from plain files on the Linux disk instead of each one
opening VPKs itself. Unit 003 is the first consumer. It needs
`resource/localization/citadel_generated_vo/*.dat` from `citadel` and from
every `citadel_<lang>` VPK, plus `soundevents/vo/*.vsndevts_c` and
`sounds/vo/**`.

Decided:
- It covers every `pak01_dir.vpk` under `game/`: `citadel`, `core`, and each
  `citadel_<lang>`. Each pak gets its own tree, keyed by its game directory
  name, and nothing is merged, so overlay order stays the consumer's call.
- It writes raw bytes with no decompiling. Decompiling with VRF is a
  per-consumer step downstream.
- It is a redo target under `data/`, gitignored, rebuilt when the VPK or the
  code changes.
- Consumers can ask for a subset (a path prefix or glob). Exploding
  everything must also be possible.

For you to settle and report:
- The target naming and how a consumer asks for a subset. Measure the
  full-explode size and time, and decide whether full explode is the default
  or opt-in.
  **Amended after the crash:** your full `citadel` explode filled C: and
  crashed the session (see the Disk rule in this kb's `CLAUDE.md`). Delete
  `data/vpk/citadel.d.redo.tmp.tmp` and any other partial output. Don't
  run a full explode again: compute its size from the index, time a subset
  and extrapolate. Full explode stays opt-in, and its `.do` refuses to run
  when the index total plus 20 GB exceeds C:'s free space. Record the
  vhdx-on-C: fact in `docs/dev/environment.kb/host-alpine-musl-gcompat.md`.
- Whether `extract.py` (which decompiles and covers `citadel` only) is now
  redundant or should become explode plus decompile. If it is redundant,
  name it in Open Questions and leave it in place.
- Write the decision in `docs/dev/decisions.kb/`. Put any VPK-layout facts
  you learn, such as which locale paks hold which files, in
  `formats.kb/vpk-v2-container.md` or `environment.kb/game-install-paths.md`.

## Decisions

Target grammar, subset by directory, opt-in full explode, own byte reader:
`docs/dev/decisions.kb/explode-vpks-to-plain-files.md`.
- `extract.py` kept as is: it decompiles `vdata_c` straight from the VPK
  through VRF for `gamedata.list`, which `data/vpk/` does not replace by
  itself (see Open Questions).
- Reused `archive.Entry`/`read_entries` for the index rather than a new
  type; `select` asserts `preload_length == 0` (true of every pak today)
  instead of carrying preload bytes nobody ships.

## Open Questions

- `extract.py` is not redundant yet, but could become
  `data/vpk/citadel/scripts.d` (etc.) plus a VRF decompile of that tree,
  which would give VRF fast local reads. Owner's call whether that's
  worth a unit.
- The brief's `citadel_generated_vo/*.dat` premise is stale: captions are
  loose `.txt` under `citadel/resource/localization/`, every language in
  `citadel/`, none in any pak (recorded in `game-install-paths.md`). 003
  reads them in place; `data/vpk/` does not cover loose files.

## Final report

Checks: `./bin/shell pytest` and `pyright` clean (both green before the
unit too); new files `black`-clean.

Built and kept: `data/vpk/citadel/sounds/vo.d` (83,015 files, 2.6 GiB,
74 s), `citadel/soundevents/vo.d` (61 files), `core.d`, `citadel_french.d`.
No-op rebuild 0.2 s. Every file CRC-checked on write. The crashed full
`citadel.d` partial (22.5 GB) is deleted; C: has 82 GB free. Full-explode
size comes from the indexes (citadel 34.5 GB, core 0.65 GB, locales
0.02 GB each); the guard refused a real full `citadel` run in a dry check
with the reserve raised.

Deviations:
- **Outside the file list:** appended `DEADLOCK_FREE_SPACE_DIR="/mnt/c"`
  to the gitignored `localhost.env`. Without it, the guard checks `/`
  and cannot protect this box. Keeping C: out of the code follows
  `machine-local-paths-live-in-localhost-env.md`.
- Subsets are directories, not globs (reason in the decision file).
- The guard covers every explode, not only `all`: it lives in `explode.py`.

Where things live: the target grammar is in `data/vpk/default.d.do` and
