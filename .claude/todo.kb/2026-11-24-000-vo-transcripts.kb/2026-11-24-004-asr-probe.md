# `asr probe`: settle the open ASR questions before the full run

**Parent:** <https:../2026-11-24-000-vo-transcripts.md> (wave 3)

## Problem Statement

Unit 005 will transcribe all 1806 Yamato VO clips in the background,
following the proposed design in
`docs/dev/decisions.kb/ml-observations-are-committed-ledgers.md`. A POC on
16 clips with large-v3-turbo has already run (the plan's bullets, and
`trash/vo-transcripts/poc/`). Before 005 is briefed, measure what that
design still guesses at, so the brief carries numbers instead of guesses.

Use the POC's 16 clips as the fixed test set (its `out.turbo/*.txt` is the
baseline), plus any clips a question needs. The clips are in
`trash/vo-transcripts/002/bulk/sounds/vo/yamato/` and the turbo model is in
`trash/vo-transcripts/poc/models/`. Everything here is investigation:
scratch and models go in `trash/vo-transcripts/004/`. Don't build pipeline
code.

Questions, in order of how much they could change the design:

1. **Batching.** Can several clips share one encoder window? Concatenate
   about 5 to 10 same-language clips with about 1 s of silence between them
   (ffmpeg), transcribe with `-l ja`, and split the output back by segment
   timestamps. Does each clip's text match its solo run, and is the
   clip-to-segment mapping reliable? Report the speedup per clip.
   Language detection would then be a separate per-clip `-dl` pass, so
   measure that pass on its own: does `-ac` shrink its cost?
2. **Model.** Compare speed and the Japanese and English text on the test
   set for turbo f16 (baseline), turbo `q5_0`, turbo `q8_0`, and large-v3
   `q5_0`, from `huggingface.co/ggerganov/whisper.cpp`. Check disk first
   (Disk rule). Recommend one.
3. **Prompt.** Build a proper-noun prompt from the game's own names: hero
   names from `citadel_gc_hero_names` (the lookup package loads it), in
   English and, if a Japanese file exists among the loose localization
   files, in Japanese. Do the 6 English clips come out right ("Lash, down
   there", Calico, and the `nurse` hero's display name)? Do the Japanese
   ones get worse? Does a prompt shift `-dl`'s detection?
4. **Detection confidence.** Record the `-dl` language and `p` for all 16
   clips, then for about 50 more English-looking clips (`ping/`, shop
   reminders). Is the design's `p < 0.8` threshold right?
5. **Throughput layout.** Compare 1 process at 4 threads, 2 at 2 threads,
   and 3 at 4 threads. Report clips per hour and how responsive the machine
   stays (load, and whether a foreground `pytest` slows down). The owner
   wants to keep working in the foreground during the run.
6. **CRC stability.** `data/manifest.jsonl` is from an older build and holds
   `crc32` for every `vsnd_c`. Compare it against the current pak index for
   Yamato's VO. How many unchanged paths kept their CRC? That tells us
   whether CRC keying will rerun only the clips that really changed.

Write the durable findings (tool behavior, speeds, flags on this host) into
a new `docs/dev/environment.kb/whisper-asr.md`, and add the tooling (brew
`whisper.cpp` 1.9.5, `ffmpeg` 9.1) to `environment.kb/toolchain.md`. Archive
any script the doc cites in `docs/dev/probes/asr-*`. Put the
recommendations for 005 and for the design doc in your Final report. Don't
edit the design doc: the coordinator owns it.

**Scope (only these files):** `docs/dev/environment.kb/whisper-asr.md`
(new), `docs/dev/environment.kb/toolchain.md`, `docs/dev/probes/asr-*`,
`docs/dev/formats.kb/asset-extensions.md` (fix `vsnd_c -> wav`: VRF writes
the stored MP3), this file. Scratch: `trash/vo-transcripts/004/`.
