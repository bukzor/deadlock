# Damage and vis read the game data through the lookup

**Parent:** <https:../2026-11-23-000-package-split.md> (wave 4, beside unit 006)

## Problem Statement

Move every reader of the game data in `bukzor_deadlock_damage` and
`vis_server` onto the lookup API from unit 004:

- **Damage modules:** they keep no raw `dig` of a vdata key, and no private
  parser of `m_strValue`.
- **vis:** it keeps no loader. `queries.load_data`, `GameData` and `listed`
  give way to the lookup, and so does whatever of `names.py` remains. vis's
  synthetic test trees build through the lookup's in-memory constructor.
- **Cleanup:** remove the compatibility delegates in the lookup's
  `names.py` that nothing calls any more.

Behavior does not change: the golden check proves it. A test that pins a
raw-key detail now owned by the lookup moves to the lookup's tests, or is
deleted when a lookup test already covers it. Say which in Decisions.

If the lookup lacks something a consumer needs, add it in the lookup with
its test. Record each addition in Decisions, since unit 004 designed that
API. Its `pyproject.toml` dependencies stay fixed.

**Scope (only these files):** `packages/bukzor-deadlock-damage/src/`,
`packages/bukzor-deadlock-lookup/src/`, `apps/vis/server/src/`, and this
file
