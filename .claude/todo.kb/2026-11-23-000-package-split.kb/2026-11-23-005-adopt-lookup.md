# Damage and vis read the game data through the lookup

**Parent:** <https:../2026-11-23-000-package-split.md> (wave 3, beside unit 007)

## Problem Statement

Move every reader of the game data in `bukzor_deadlock_damage` and
`vis_server` onto the lookup API from unit 004:

- **Damage modules:** they keep no raw `dig` of a vdata key, and no private
  parser of `m_strValue`.
- **vis:** it keeps no loader. `queries.load_data`, `GameData` and `listed`
  give way to the lookup, and so does whatever of vis's `names.py` remains.
  vis's synthetic test trees build through the lookup's in-memory
  constructor.
- **Lookup `names.py`:** unit 002 moved vis's localization helpers into it,
  and unit 004 built the API without them. Merge the two so each
  localization fact is read in one place, and delete what nothing calls.

Behavior does not change: the golden check proves it. A test that pins a
raw-key detail now owned by the lookup moves to the lookup's tests, or is
deleted when a lookup test already covers it. Say which in Decisions.

If the lookup lacks something a consumer needs, add it in the lookup with
its test. Record each addition in Decisions, since unit 004 designed that
API. Its `pyproject.toml` dependencies stay fixed.

Unit 007 runs beside you. It only reads the lookup, so the lookup's
existing public names stay as unit 004 left them; additions are fine.

**Scope (only these files):** `packages/bukzor-deadlock-damage/src/`,
`packages/bukzor-deadlock-lookup/src/`, `apps/vis/server/src/`, and this
file

## Decisions

- **Damage takes the whole `Lookup`:** `guns/melee/casts.cycle(game, hero,
  ability, ...)`; `casts.card_dps(Ability, spirit)`; `boons.*` take a `Hero`.
  `casts` loses its `tokens` parameter (labels come from `game`). Damage still
  calls `bukzor_deadlock`'s readers (`bindings`, `profiles`, `upgrades`,
  `curves`) over `game.heroes`/`game.abilities`: library calls, not digs.
- **Lookup additions** (unit 004's names untouched): `Ability.text`,
  `Ability.weapon` -> `Weapon`, `Ability.attack` -> `Attack`, `Hero.scaling`
  (reuses `Scale`), `Hero.per_boon`, `Hero.grants_boon`, `Lookup.label`.
  `Weapon` keeps engine units; meters stay `guns`'s concern.
- **`names.py` deleted.** `property_label` became `Lookup.label`;
  `ability_name` inlined (`ability.name or key`); its `load_tokens` gave way to
  `load.load_tokens` (the superset; golden unchanged). Its tests: label cases
  moved to `lookup_test`, the install check to `load_test`; the ability-name
  fallback tests were deleted (`lookup_test` covers `name is None`).
- **Errors:** vis's boundary also maps `Unresolved` and `NotANumber` to
  `BadRequest`. `casts` wraps `Ability.value` so a missing or non-numeric
  field is still `BadInput`; the non-numeric message is byte-identical
  (`f"{NotANumber} this model can read"`), the missing one now says
  "is missing" (was "is None, not a number"). `melee`'s unknown hero is now
  `Unresolved` (`melee_test` updated); vis's `_kit` rejects it first anyway.
- **vis tests:** `DescribeListed` deleted (`lookup_test`'s `playable` and
  `load_test`'s heroes.tsv check cover it); `load_data() is load_data()`
  deleted (`load_test` has it). Synthetic heroes get names via tokens.
