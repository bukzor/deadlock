# `bukzor-deadlock-lookup`: typed game data, by key or English name

**Parent:** <https:../2026-11-23-000-package-split.md> (wave 2, beside 002, 003, 006)

## Problem Statement

Build the lookup API in `packages/bukzor-deadlock-lookup/src/bukzor_deadlock_lookup/`,
which unit 001 left empty and wired. In wave 3, unit 005 moves the damage
modules and vis onto it, and unit 007 the sandbox measurements. Shape the
API for those consumers; don't edit any of them here.

What the consumers do today, and what the API replaces. Read the code in
`apps/vis/server/src/vis_server/`; unit 002 is moving the damage modules
into `packages/bukzor-deadlock-damage/` as you work, without changing them.

- **vis `queries.py`** (`load_data`, `GameData`, `listed`, `_kit`): loads
  `heroes.json`, `abilities.json` and `heroes.tsv`, plus the localization
  from the install. It lists the live, playable heroes with their display
  names, and a hero's kit by slot.
- **damage modules** (`guns`, `melee`, `casts`, `boons`): about 30
  `dig(tree, key, "m_...")` calls on raw vdata keys. There are three
  private float parsers of `m_strValue` (`guns._num`, `melee._num`,
  `casts._number`), spirit scaling read from `m_subclassScaleFunction`,
  `m_bIsAbilityDamageProperty`, per-level hero stats (`boons`) and gun
  profiles.
- **sandbox measurements** (`crimson_slash_test_data.py` at the repo root,
  which unit 006 is moving): name items in English ("Tankbuster", "Mystic
  Reverb"). They need each item's key, tier, cost and slot, to assert
  constant spirit investment. English item names are in the install's
  `citadel_gc_mod_names` localization (for example, Tankbuster is
  `upgrade_magic_shock`); hero and ability names are in the files
  `vis_server/names.py`'s `load_tokens` reads.

Requirements:

- **Loading:** data is read once per process, lazily. Importing a consumer
  stays cheap and needs no data; vis reads `data/` at its first query.
- **Tests:** the lookup can be built from in-memory trees, so tests can
  pass synthetic data the way vis's `conftest.py` does today.
- **Name resolution:** a lookup takes a key or an English name. An unknown
  or ambiguous name raises, and the message names the near candidates.
  Names are resolved per kind (hero, ability, item), never across kinds.
- **Types and deps:** typed under the root's pyright (`typeCheckingMode =
  "all"`), Python 3.12, and no dependency beyond those `pyproject.toml`
  declares. If you need another, stop and report: no unit touches a lock
  this wave except 003.
- **Leave `names.py` and `names_test.py` alone:** unit 002 is moving vis's
  localization helpers into those two files in your package. Don't create
  or edit either, and don't import them yet. Your API may cover the same
  ground; unit 005 reconciles the two.
- **Tests:** beside each module (`{module}_test.py`). Include at least one
  test against the real `data/` tree and install: Tankbuster's key and its
  3200 cost, and Yamato's Crimson Slash key `citadel_ability_healing_slash`.

**Scope (only these files):** `packages/bukzor-deadlock-lookup/src/`, except
`names.py` and `names_test.py`, and this file

## Decisions

- **Entities keep their raw `tree`.** Typed readers cover what the consumers
  repeat (`Ability.value`/`scale`/`damage_properties`, `Hero.kit`/`stat`);
  anything rarer still `dig`s the tree, so unit 005 isn't blocked on a reader.
- **One parser, `entities.number`,** with casts' strict rule (numbers or an
  exact decimal string; bools and per-level lists raise `NotANumber`). guns'
  laxer `float(str)` accepts nothing the live data needs beyond that.
- **Items come from `bukzor_deadlock.items.items`** over the abilities tree
  and `generic_data`'s prices, not `items.tsv`: one builder, testable in memory.
- **Only enabled items answer to a name**; any item to its key. Real data has
  one item collision, "Silencer" (`upgrade_proc_silence` live,
  `upgrade_silencer` disabled), which would otherwise always raise.
- **`ability(ref, hero=...)` scopes to a kit.** 12 English ability names
  collide across all abilities (every melee is "Melee"; "Sticky Bomb" x2).
- **`playable()` matches vis's `heroes` query** (bindings-live, named, not
  dummy/Generic Person); the real-data test checks it against `heroes.tsv`.
- **`load_tokens` merges four files** (hero, ability, item names; property
  labels), dropping each file's `Language` header, which differs by file.
