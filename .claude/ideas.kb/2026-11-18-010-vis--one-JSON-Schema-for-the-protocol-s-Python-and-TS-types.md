# vis: one JSON Schema for the protocol's Python and TS types

## The Idea

The protocol is written three times and nothing checks them against each
other: the design's "Protocol" tables (`docs/dev/decisions.kb/vis-app.md`),
the server's untyped `JsonObj` lines (`queries.py`: `_hit`, `_measure`,
`_note`, the inline `cycle` dict, `TIMELINE`'s descriptions), and the
client's hand-written `client/src/protocol.ts`, which `api.ts` casts to
without validating. A server field change breaks the client silently.

Write the protocol once, as `apps/vis/protocol.jsonschema.yaml`, and generate
both sides from it:

- Python: `datamodel-codegen --output-model-type msgspec.Struct --use-default`
  → tagged msgspec Structs. `Query.run` returns them; `JsonObj` leaves the
  protocol; `_hit`/`_measure`/`_note` go.
- TS: `json-schema-to-typescript` → `protocol.ts`.

> time is out.

### Each field is in one of three states

JSON Schema keeps `required` and `default` independent, which is why it was
chosen over TypeSpec (no default on a required property, unverified),
protobuf (zero-value defaults; its JSON omits them), Smithy (AWS/JVM
tooling) and CUE (exports to JSON Schema anyway).

| state | schema | Python | TS |
|---|---|---|---|
| required | in `required`, no `default` | no default | `x: T` |
| defaulted: a constructor convenience, always sent | in `required`, with `default` | `x: T = d` | `x: T` |
| optional: the reader applies the default (request params; future-proofing) | not in `required`, with `default` | `x: T \| UnsetType = d` | `x?: T` |

A probe confirmed all three rows and the `kind`-tagged union through both
generators (2026-11-18; `Hit.cycle` defaulted, `TimelineParams.level`
optional). The probe lived in the gitignored `trash/typeddict/`.

## Exploration Notes

- Freshness: the generated files are gitignored and regenerated by every
  consumer, never committed (committed generated code drifts).
  - TS: `gen` runs before `check`/`build`/`test`, from `postinstall`, and
    from a Vite plugin watching the schema in the dev loop.
  - Python has no run-before-use hook: a `redo` target, plus a test that
    regenerates in memory and fails on a difference. Unsolved: pyright and
    pytest on a fresh checkout before the first `redo`.
- `timeline.Hit` and `measures.Measure` become generated, or the copy
  functions stay. Generating them loses nothing today: neither has methods.
- The generated Structs aren't `frozen`; find the flag. The output also
  carries a timestamp header (look for a flag to disable it).
- The params schema's `description`s feed `GET /api`'s listing, replacing
  `TIMELINE`'s dict and the hand-copied JSDoc on `TimelineParams`.
- The design's field tables point to the schema and keep only the meaning
  (half-open window, `trigger` vs `land`). `protocol.ts`'s optional
  `max_horizon?`/`label?` (hedging for "older servers") go: client and
  server ship from one checkout.
- Run-time validation (Ajv over the same schema) is deferred: compile-time
  types catch drift when both sides come from one checkout.
- The runner-up is Python as the source (msgspec Structs; response schemas
  post-processed so every field is required except `UnsetType` ones): one
  derived file instead of two. It wins if keeping generated Python fresh
  proves awkward.
