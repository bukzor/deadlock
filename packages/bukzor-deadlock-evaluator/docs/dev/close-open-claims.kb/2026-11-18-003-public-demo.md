# `public demo`: obtain one real public match demo

**Parent:** <../close-open-claims.md> (wave 1)

## Problem Statement

Goal: the seven local demos are bot matches, which may be lighter in
event density than human matches. Obtain one public ranked or
unranked match `.dem` so unit 002 can compare. Consumers: units 002
and 004.

Known routes, unverified: the in-game Watch tab downloads replays into
`game/citadel/replays/` (that directory exists and is empty); public
APIs (e.g. deadlock-api.com) list matches with `demo_url` fields pointing
at Valve's replay CDN (`.dem.bz2`). Prefer the API route since it needs
no game client; fall back to documenting the in-game steps for the
owner if every API needs a key we lack. Fetch only public match data;
never anything that needs the owner's credentials.

Store the demo under `data/replays/` (create it; it must be gitignored
like the rest of `data/` except `.do` files). Record how it was
obtained as a redo recipe `data/replays/<match-id>.dem.do` if the route
is scriptable; otherwise as prose in a new claim
`../claims.kb/tooling.kb/public-match-demos-source.md`
(`standing: agent`, `why:` the parser claim) that names the route,
the metadata the API exposes per match (rank bracket, patch, duration),
and any rate limit. Write that claim either way: the route is a fact the
design needs.

**Scope (only these files):** `data/replays/**`, the `.gitignore` line if
one is needed, `../claims.kb/tooling.kb/public-match-demos-source.md`,
this file.

## Steps

- [x] Survey deadlock-api.com's OpenAPI: `/v1/matches/metadata` (bulk,
  filterable), `/v1/matches/{id}/salts` (yields `demo_url`), rate limits.
- [x] Pick one recent public ranked match of normal length; fetch its salts.
- [x] Download the `.dem.bz2`, decompress to `data/replays/<id>.dem`; verify
  the Source 2 demo magic (`PBDEMS2`).
- [x] Script the route as `data/replays/default.dem.do` and
  `default.salts.json.do`; gitignore `data/replays/*` except `.do`.
- [x] Write `../claims.kb/tooling.kb/public-match-demos-source.md`; validate.
- [x] Commit scope + this file.

## Decisions

- Pattern recipes (`default.*.do`), not `<match-id>.dem.do`: the route is
  the same for every match; the id is the target name. Two targets, not
  three: the compressed stream is decompressed in flight, so no 240 MB
  intermediate.
- Match 139163969 (2026-11-17, ranked, Oracle 4 average, 34.5 min, a day
  old so its salts were stored): a typical-length high-bracket game.
- The payload is zstd, not bzip2, despite the `.dem.bz2` name. No zstd
  binary on the box and the venv pins 3.12, so the recipe decompresses
  with CPython 3.14's stdlib via `uv run --python 3.14 --no-project`,
  sniffing the magic so a real bzip2 still works. Did not `apt install
  zstd` (machine state is the owner's) nor `uv add` (lock is out of scope).
- `.dem.do` writes `$3`, not stdout, so it can check the demo magic.
- No `shellcheck` on the box; the recipes are unchecked beyond running.

## Open Questions

- `game/citadel/replays/` is not empty, contrary to the brief: four
  Watch-tab demos (78292581, 81863306, 87052930, 107527112; Apr-Sep 2026;
  490-660 MB) and ~40 `auto-*.dem` recordings of the owner's own games.
  Home would be `docs/dev/environment.kb/game-install-paths.md` (repo
  root), out of scope. Older patches, but free material for 002/004.
- Replays expire (CDN `x-goog-custom-time` = match + 10 days); the stored
  demo is the durable artifact, the recipe will 404 after ~2026-11-27.
