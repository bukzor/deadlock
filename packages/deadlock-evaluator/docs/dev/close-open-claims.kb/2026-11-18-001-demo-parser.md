# `demo parser`: pick and vendor a Deadlock demo parser, prove it on a local demo

**Parent:** <../close-open-claims.md> (wave 1)

## Problem Statement

Goal: `observe` will wrap an existing Source 2 demo parser. Find the one
that parses current Deadlock `.dem` files, get it runnable in this repo,
and prove it on `game/citadel/botmatch1.dem` from the game install.
Consumers: unit 002 (counts rows by event type) and unit 004 (needs
damage events with positions and tick), so the proof must show what the
parser exposes.

Candidates to survey first (the agent in the design conversation named
these from memory; verify): `haste` (Rust, github.com/blukai/haste,
claims Deadlock support), `manta` (Go, Dota 2), `demofile-net` (C#),
`clarity` (Java). Prefer Rust or a prebuilt release. Reject anything
that does not parse the current patch's demo.

Vendoring: a redo recipe under `data/tools/` on the Source2Viewer
pattern when the parser ships a release binary; when it must be built
from source, a `.do` that runs `cargo build --release` into
`data/tools/<name>.d/` is acceptable (rustup is available). If the build
exceeds the timebox, leave the manual build in `trash/unit-001/`,
document the commands in the Final report, and say so.

Report, in `reuse-a-demo-parser.md`: parser name, version/commit, how it
is invoked, and which of these it exposes per event: tick, game time,
entity positions, combat-log damage events with attacker/victim/amount,
item purchases, ability casts, souls. Each exposed item is one line.

**Scope (only these files):** `data/tools/<parser>*` and their `.do` files;
`../claims.kb/tooling.kb/reuse-a-demo-parser.md`; this file.
